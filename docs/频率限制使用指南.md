# API 频率限制（Rate Limiting）使用指南

> **版本**: 1.0.0  
> **日期**: 2026-02-08  
> **目的**: 防止API滥用、DDoS攻击，保护服务器资源

---

## 📋 概述

MarketBook项目已集成请求频率限制中间件，为不同类型的API提供差异化的限流策略。

**核心功能**:
- ✅ 防止恶意用户暴力攻击（如密码爆破）
- ✅ 防止DDoS攻击和API滥用
- ✅ 保护服务器资源，确保服务稳定性
- ✅ 差异化限流策略（认证、交易、查询、行情）
- ✅ 标准HTTP响应头（X-RateLimit-*）
- ✅ 内存存储（生产环境可升级为Redis）

---

## 🎯 当前限流策略

### 1. 认证相关 API（rateLimitPresets.auth）
**适用场景**: 注册、登录  
**限制**: 15分钟内最多 **20次** 请求  
**超限提示**: "认证请求过于频繁，请稍后再试"

**应用接口**:
- `POST /api/auth/register` - 用户注册
- `POST /api/auth/login` - 用户登录

---

### 2. 严格限流（rateLimitPresets.strict）
**适用场景**: 敏感操作（刷新令牌、密码重置）  
**限制**: 1分钟内最多 **5次** 请求  
**超限提示**: "操作过于频繁，请1分钟后再试"

**应用接口**:
- `POST /api/auth/refresh` - 刷新令牌

---

### 3. 交易操作（rateLimitPresets.trading）
**适用场景**: 下单、创建账户等写操作  
**限制**: 1分钟内最多 **30次** 请求  
**超限提示**: "交易请求过于频繁，请稍后再试"

**应用接口**:
- `POST /api/trading/accounts` - 创建交易账户
- `POST /api/trading/orders/buy` - 买入下单
- `POST /api/trading/orders/sell` - 卖出下单

---

### 4. 查询操作（rateLimitPresets.query）
**适用场景**: 持仓查询、交易历史、账户信息  
**限制**: 1分钟内最多 **60次** 请求  
**超限提示**: "查询请求过于频繁，请稍后再试"

**应用接口**:
- `GET /api/trading/accounts` - 查询用户账户
- `GET /api/trading/accounts/:accountId` - 查询账户详情
- `GET /api/trading/accounts/:accountId/positions` - 查询持仓
- `GET /api/trading/accounts/:accountId/history` - 查询交易历史

---

### 5. 行情查询（rateLimitPresets.market）
**适用场景**: 实时行情、批量行情、股票搜索  
**限制**: 1分钟内最多 **120次** 请求（最宽松，支持实时刷新）  
**超限提示**: "行情查询过于频繁，请稍后再试"

**应用接口**:
- `GET /api/trading/quotes/:symbol` - 单个股票行情
- `GET /api/trading/quotes?symbols=AAPL,GOOGL` - 批量行情
- `GET /api/trading/market/symbols?keyword=apple` - 股票搜索

## 📊 响应格式

### 正常请求响应头
```http
HTTP/1.1 200 OK
X-RateLimit-Limit: 100            # 时间窗口内的最大请求数
X-RateLimit-Remaining: 85         # 剩余可用请求数
X-RateLimit-Reset: 2026-02-08T08:23:30.458Z  # 限流重置时间
```

### 超限响应（429 Too Many Requests）
```json
{
  "success": false,
  "error": {
    "type": "TOO_MANY_REQUESTS",
    "message": "请求过于频繁，请稍后再试",
    "statusCode": 429,
    "errorId": "err_1707378210458_abc123",
    "timestamp": "2026-02-08T08:23:30.458Z",
    "details": {
      "retryAfter": 45,           // 建议等待秒数
      "limit": 100,               // 限流阈值
      "windowMs": 900000          // 时间窗口（毫秒）
    }
  }
}
```

**响应头**:
```http
HTTP/1.1 429 Too Many Requests
X-RateLimit-Limit: 100
X-RateLimit-Remaining: 0
X-RateLimit-Reset: 2026-02-08T08:24:15.458Z
Retry-After: 45                    # 建议等待秒数
```

## 🛠️ 开发者使用指南

### 基础用法

```javascript
const { rateLimitPresets } = require('../middlewares/rateLimiter');

// 应用预设限流策略
router.post('/api/auth/login', rateLimitPresets.auth, loginController);
```

### 自定义限流策略

```javascript
const { rateLimiter } = require('../middlewares/rateLimiter');

// 自定义限流配置
const customLimiter = rateLimiter({
  windowMs: 60 * 1000,      // 时间窗口：1分钟
  maxRequests: 10,          // 最大请求数：10次
  message: '自定义超限提示'
});

router.post('/api/custom', customLimiter, customController);
```

### 基于用户ID限流（已登录用户）

```javascript
const { rateLimitPresets } = require('../middlewares/rateLimiter');

// 使用用户ID而非IP地址作为限流键
const userLimiter = rateLimitPresets.perUser({
  windowMs: 60 * 1000,
  maxRequests: 50
});

router.get('/api/profile', authenticateToken, userLimiter, profileController);
```

## ⚠️ 注意事项

### 1. 生产环境升级建议

当前使用 **内存存储**（Map），适合单机部署。生产环境建议升级为：

- **Redis**: 支持集群、持久化、更高性能
- **示例**: 使用 `rate-limit-redis` 包

```javascript
const RedisStore = require('rate-limit-redis');
const redis = require('redis');

const client = redis.createClient();

const limiter = rateLimiter({
  store: new RedisStore({
    client: client,
    prefix: 'rate_limit:'
  }),
  windowMs: 15 * 60 * 1000,
  maxRequests: 100
});
```

### 2. 负载均衡场景

如果使用负载均衡（多台服务器），必须使用 **Redis** 或其他共享存储，否则每台服务器独立计数，限流失效。

### 3. IP获取准确性

如果服务器前有反向代理（Nginx、Cloudflare），需配置 `trust proxy`：

```javascript
// app.js
app.set('trust proxy', 1);  // 信任第一层代理
```

这样 `req.ip` 才能获取到真实客户端IP，而不是代理IP。

### 4. 定制化密钥生成

根据业务需求自定义限流键：

```javascript
// 基于 IP + User Agent 组合限流（防止同一用户用多个浏览器绕过限制）
const customLimiter = rateLimiter({
  keyGenerator: (req) => {
    const ip = req.ip;
    const userAgent = req.get('User-Agent') || 'unknown';
    return `${ip}:${userAgent.substring(0, 50)}`;
  }
});
```

## 📈 性能影响

### 内存占用

- **每条记录**: ~100 bytes（key + count + resetTime）
- **1000个并发用户**: ~100 KB
- **10000个并发用户**: ~1 MB

**结论**: 内存占用非常小，完全可接受。

### 自动清理机制

定时器每 **60秒** 自动清理过期记录，防止内存泄漏。
