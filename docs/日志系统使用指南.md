# 日志系统使用指南

## 概览

MarketBook 使用基于 Winston 的结构化日志系统，提供：
- ✅ 文件轮转（自动按大小/时间切割）
- ✅ 多级别日志（debug/info/warn/error）
- ✅ 上下文信息（请求ID、用户ID等）
- ✅ 错误追踪（堆栈信息）
- ✅ 审计日志（敏感操作记录）
- ✅ 性能监控（慢查询、慢接口）

## 快速开始

### 1. 基础用法

```javascript
const logger = require('./utils/logger');

// 记录不同级别的日志
logger.debug('Debug information');
logger.info('Application started');
logger.warn('Warning: high memory usage');
logger.error('Error occurred');
```

### 2. 带元数据的日志

```javascript
logger.info('User logged in', {
  userId: 'user123',
  email: 'user@example.com',
  ip: '192.168.1.1',
});
```

### 3. 错误日志

```javascript
const { logError } = require('./utils/logger');

try {
  // 业务逻辑
} catch (error) {
  logError(error, {
    userId: req.userId,
    action: 'create_account',
  });
}
```

## 日志级别

日志系统支持 4 个级别（优先级从高到低）：

| 级别 | 用途 | 示例 |
|------|------|------|
| `error` | 错误和异常 | 数据库连接失败、API调用失败 |
| `warn` | 警告信息 | 高内存使用、慢查询 |
| `info` | 常规信息 | 用户登录、交易成功 |
| `debug` | 调试信息 | 函数调用参数、中间结果 |

### 配置日志级别

```bash
# .env
LOG_LEVEL=info  # 只记录 info 及以上级别（info, warn, error）
```

在开发环境建议使用 `debug`，生产环境使用 `info`。

## 日志输出

### 1. 控制台输出

开发环境彩色输出，方便调试：

```bash
[2026-02-08 19:00:00] INFO: User logged in { userId: 'user123' }
[2026-02-08 19:00:01] ERROR: Database connection failed
```

### 2. 文件输出

日志自动写入文件，支持轮转：

```
logs/
├── combined.log       # 所有日志
├── error.log          # 仅错误日志
├── exceptions.log     # 未捕获异常
└── rejections.log     # 未处理的Promise rejection
```

**轮转配置**：
- 单文件最大 10MB
- 保留最近 7 天

### 3. JSON 格式（生产环境）

生产环境使用 JSON 格式，便于日志收集系统解析：

```json
{
  "timestamp": "2026-02-08T11:00:00.000Z",
  "level": "info",
  "message": "User logged in",
  "userId": "user123",
  "email": "user@example.com"
}
```

## 高级用法

### 1. 子日志器（带上下文）

为特定模块创建带上下文的日志器：

```javascript
const { createChildLogger } = require('./utils/logger');

const logger = createChildLogger('AuthService');

logger.info('User registered');  
// 输出: [2026-02-08 19:00:00] INFO: User registered { context: 'AuthService' }
```

### 2. HTTP 请求日志中间件

自动记录所有 HTTP 请求：

```javascript
const { httpLogger } = require('./utils/logger');

app.use(httpLogger);

// 自动记录：
// [2026-02-08 19:00:00] INFO: HTTP Request {
//   method: 'POST',
//   path: '/api/auth/login',
//   statusCode: 200,
//   duration: '45ms',
//   userId: 'user123'
// }
```

### 3. 审计日志（敏感操作）

记录用户关键操作，用于安全审计：

```javascript
const { auditLog } = require('./utils/logger');

// 用户登录
auditLog('USER_LOGIN', userId, {
  email: 'user@example.com',
  ip: req.ip,
});

// 交易操作
auditLog('TRADE_EXECUTED', userId, {
  symbol: 'AAPL',
  type: 'BUY',
  quantity: 100,
  price: 176.16,
});

// 权限变更
auditLog('ROLE_CHANGED', userId, {
  oldRole: 'user',
  newRole: 'admin',
  changedBy: 'admin123',
});
```

### 4. 性能监控

监控慢查询和慢接口：

```javascript
const { performanceLog } = require('./utils/logger');

const startTime = Date.now();

// 执行数据库查询
const result = await db.query('SELECT * FROM users');

const duration = Date.now() - startTime;
performanceLog('Database Query', duration, 1000);  // 超过1秒记录警告
```

### 5. 调试日志（仅开发环境）

避免生产环境打印敏感调试信息：

```javascript
const { debugLog } = require('./utils/logger');

debugLog('Function called with params', {
  userId: 'user123',
  params: { symbol: 'AAPL', quantity: 100 },
});
// 仅在 NODE_ENV=development 时输出
```

## 实战示例

### 示例 1：控制器中使用

```javascript
const { logError, auditLog } = require('../utils/logger');

async function login(req, res, next) {
  try {
    const { email, password } = req.body;
    
    const user = await authService.login(email, password);
    
    // 记录审计日志
    auditLog('USER_LOGIN', user.id, {
      email: user.email,
      ip: req.ip,
      userAgent: req.get('user-agent'),
    });
    
    res.json({ token: user.token });
  } catch (error) {
    // 记录错误日志
    logError(error, {
      action: 'login',
      email: req.body.email,
      ip: req.ip,
    });
    
    next(error);
  }
}
```

### 示例 2：服务层中使用

```javascript
const { createChildLogger, performanceLog } = require('../utils/logger');

const logger = createChildLogger('TradingService');

async function executeTrade(userId, symbol, type, quantity, price) {
  const startTime = Date.now();
  
  logger.info('Executing trade', {
    userId,
    symbol,
    type,
    quantity,
    price,
  });
  
  try {
    // 执行交易逻辑
    const result = await tradeEngine.execute({ userId, symbol, type, quantity, price });
    
    const duration = Date.now() - startTime;
    performanceLog('Trade Execution', duration, 500);  // 超过500ms警告
    
    logger.info('Trade executed successfully', {
      tradeId: result.id,
      duration: `${duration}ms`,
    });
    
    return result;
  } catch (error) {
    logger.error('Trade execution failed', {
      error: error.message,
      userId,
      symbol,
    });
    throw error;
  }
}
```

### 示例 3：错误处理中间件中使用

```javascript
const { logError } = require('../utils/logger');

function errorHandler(err, req, res, next) {
  // 记录错误详情
  logError(err, {
    method: req.method,
    path: req.path,
    userId: req.userId,
    body: req.body,
  });
  
  res.status(err.statusCode || 500).json({
    success: false,
    message: err.message,
  });
}
```

## 日志配置

### 环境变量配置

```bash
# .env

# 日志级别：debug | info | warn | error
LOG_LEVEL=info

# 日志格式：json | simple | combined
LOG_FORMAT=json

# 文件输出
LOG_FILE_ENABLED=true
LOG_DIR=logs
LOG_MAX_SIZE=10m
LOG_MAX_FILES=7d

# 控制台输出
LOG_CONSOLE_ENABLED=true

# 错误日志单独配置
LOG_ERROR_ENABLED=true
```

### 代码配置

```javascript
// src/config/index.js
const logging = {
  level: process.env.LOG_LEVEL || 'debug',
  format: process.env.LOG_FORMAT || 'json',
  file: {
    enabled: process.env.LOG_FILE_ENABLED !== 'false',
    dirname: process.env.LOG_DIR || 'logs',
    maxSize: process.env.LOG_MAX_SIZE || '10m',
    maxFiles: process.env.LOG_MAX_FILES || '7d',
  },
};
```

## 日志分析

### 查看日志

```bash
# 实时查看所有日志
tail -f logs/combined.log

# 实时查看错误日志
tail -f logs/error.log

# 搜索特定用户的日志
grep 'user123' logs/combined.log

# 搜索特定时间段的日志
grep '2026-02-08 19:' logs/combined.log
```

### 日志分析工具

推荐使用以下工具分析日志：

1. **本地分析**：`grep`, `awk`, `jq`
2. **日志收集**：ELK Stack (Elasticsearch + Logstash + Kibana)
3. **云服务**：AWS CloudWatch、Google Cloud Logging
4. **错误监控**：Sentry、Rollbar

### 示例：分析慢查询

```bash
# 查找所有慢查询
grep 'Slow Operation' logs/combined.log | jq .

# 统计慢查询数量
grep 'Slow Operation' logs/combined.log | wc -l

# 按操作类型分组
grep 'Slow Operation' logs/combined.log | jq -r '.operation' | sort | uniq -c
```

## 最佳实践

### 1. 日志级别选择

```javascript
// ✅ 正确使用日志级别
logger.debug('Function called with params', { userId, params });  // 调试信息
logger.info('User logged in', { userId });                        // 常规信息
logger.warn('High memory usage detected', { usage: '85%' });      // 警告信息
logger.error('Database connection failed', { error });            // 错误信息

// ❌ 错误使用
logger.info('Function called with params', { userId, params });   // 过多细节
logger.error('User logged in', { userId });                       // 级别不当
```

### 2. 包含上下文信息

```javascript
// ✅ 包含足够的上下文
logger.error('Trade execution failed', {
  userId: 'user123',
  symbol: 'AAPL',
  type: 'BUY',
  quantity: 100,
  error: error.message,
});

// ❌ 缺少上下文
logger.error('Trade failed');
```

### 3. 避免敏感信息泄露

```javascript
// ✅ 不记录敏感信息
logger.info('User authenticated', {
  userId: user.id,
  email: user.email,
});

// ❌ 记录了密码
logger.info('User authenticated', {
  email: user.email,
  password: req.body.password,  // ⚠️ 安全隐患
});
```

### 4. 使用结构化日志

```javascript
// ✅ 结构化日志（易于解析）
logger.info('Trade executed', {
  tradeId: '12345',
  symbol: 'AAPL',
  quantity: 100,
  price: 176.16,
});

// ❌ 字符串拼接（难以解析）
logger.info(`Trade ${tradeId} executed: ${symbol} x ${quantity} @ ${price}`);
```

### 5. 性能优化

```javascript
// ✅ 避免昂贵的日志操作
if (logger.level === 'debug') {
  logger.debug('Complex object', JSON.stringify(largeObject));
}

// ❌ 无条件的昂贵操作
logger.debug('Complex object', JSON.stringify(largeObject));  // 即使不输出也会执行
```

## 故障排查

### 问题 1：日志文件过大

**症状**：日志文件占用大量磁盘空间

**解决方案**：
1. 调整日志保留时间：`LOG_MAX_FILES=3d`（保留3天）
2. 减小单文件大小：`LOG_MAX_SIZE=5m`（5MB）
3. 提高日志级别：`LOG_LEVEL=warn`（只记录警告和错误）

### 问题 2：日志丢失

**症状**：部分日志未写入文件

**解决方案**：
1. 确保日志目录有写权限：`chmod 755 logs`
2. 检查磁盘空间：`df -h`
3. 查看异常日志：`cat logs/exceptions.log`

### 问题 3：性能影响

**症状**：日志记录导致应用变慢

**解决方案**：
1. 提高日志级别（减少日志量）
2. 禁用控制台输出（生产环境）：`LOG_CONSOLE_ENABLED=false`
3. 使用异步日志传输（Winston 默认支持）
